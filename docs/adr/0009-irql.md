# ADR-0009: Interrupt request levels

- Status: Accepted (provisional until the Wave 2 gate). Amended 2026-10-31, RFC-0001
- Date: 2026-10-30
- Owner: A01, with A03 and A05

## Decision

Kamos-NT has four execution levels. Their semantics are defined here, not inherited.

| Level | Value | Code that runs there | May block | May touch pageable memory | May allocate |
|---|---|---|---|---|---|
| `PASSIVE_LEVEL` | 0 | Threads, system calls | Yes | Yes (when paging exists) | Yes |
| `DISPATCH_LEVEL` | 2 | Scheduler, deferred procedure calls, spinlock holders | No | No | Non-paged pool only |
| `DEVICE_LEVEL` | 12 | Device interrupt handlers | No | No | No |
| `HIGH_LEVEL` | 15 | NMI, machine check, panic path | No | No | No |

- **v0.1 mechanism (amendment 2026-10-31, RFC-0001).** Under the legacy PIC the CR8 task
  priority masks nothing, so v0.1 keeps the level in a per-CPU variable and enforces it in
  software:
  - `DEVICE_LEVEL` and above run with `RFLAGS.IF` clear. Raising to `DEVICE_LEVEL` is `cli`
    and lowering below it is `sti`. Every PIC line is a `DEVICE_LEVEL` interrupt.
  - `DISPATCH_LEVEL` is software only. The scheduler and deferred procedure calls are software
    interrupts kept as pending bits in the per-CPU state. They run when the level drops below
    `DISPATCH_LEVEL`, and at the end of a `DEVICE_LEVEL` handler that interrupted code running
    below it.
  - The timer handler requests the dispatch software interrupt. It never switches threads
    itself.
  - `HIGH_LEVEL` is the level of NMI, machine check and the panic path, which cannot be masked.
  - The numeric values keep their order so that, when the local APIC replaces the PIC (M-SMP),
    `KeRaiseIrql` can also write CR8 without changing any caller. Moving to the APIC is an RFC.
- **Interrupt flag and level (RFC-0002).** `IF` is clear exactly when the level is
  `DEVICE_LEVEL` or above, or inside a `HalDisableInterrupts` section. Such a section is a leaf:
  it raises no level, does not block and does not call `KeLowerIrql`. `KeLowerIrql` below
  `DEVICE_LEVEL` sets `IF`; debug builds assert that no such section is open.
- **Time does not count ticks (RFC-0002).** `HalQueryMonotonicTime` is derived from the TSC
  calibrated against the PIT, not from a tick counter. Console output at `DEVICE_LEVEL` is slow on
  real hardware and can make the PIT lose ticks, which must not make the clock run slow. QEMU will
  not show this loss; it is a known untested risk until real hardware.
- Work that a higher level hands to a lower one: a `DEVICE_LEVEL` handler queues a DPC (runs
  at `DISPATCH_LEVEL`); code at `DISPATCH_LEVEL` or above queues a work item (runs at
  `PASSIVE_LEVEL` on a system thread). Both objects are embedded in the caller's structure, so
  queueing never allocates (`ke.h`).
- `KeRaiseIrql` and `KeLowerIrql` assert that raising goes up and lowering goes down.
- A spinlock raises to `DISPATCH_LEVEL`; an interrupt-safe spinlock raises to
  `DEVICE_LEVEL`. Blocking waits assert `PASSIVE_LEVEL`; a wait with a zero timeout is allowed up to
  `DISPATCH_LEVEL`.
- Debug builds check the level at every lock acquire, pool allocation and wait.

## Consequences

`docs/architecture/lock-order.md` records, for each lock, the level at which it is taken.
