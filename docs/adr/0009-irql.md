# ADR-0009: Interrupt request levels

- Status: Accepted (provisional until the Wave 2 gate)
- Date: 2026-10-30
- Owner: A01, with A03 and A05

## Decision

Kamos-NT has four execution levels. Their semantics are defined here, not inherited.

| Level | Value | Code that runs there | May block | May touch pageable memory | May allocate |
|---|---|---|---|---|---|
| `PASSIVE_LEVEL` | 0 | Threads, system calls | Yes | Yes (when paging exists) | Yes |
| `DISPATCH_LEVEL` | 2 | Scheduler, deferred procedure calls, spinlock holders | No | No | Non-paged pool only |
| `DEVICE_LEVEL` | 12 | Device interrupt handlers | No | No | No |
| `HIGH_LEVEL` | 15 | NMI, machine check, panic path | No | No | No |

- The level is stored in CR8 (task priority), values chosen so the 4-bit CR8 classes keep
  their order when the local APIC replaces the PIC.
- `KeRaiseIrql` and `KeLowerIrql` assert that raising goes up and lowering goes down.
- A spinlock raises to `DISPATCH_LEVEL`; an interrupt-safe spinlock raises to
  `DEVICE_LEVEL`. Blocking waits assert `PASSIVE_LEVEL`.
- Debug builds check the level at every lock acquire, pool allocation and wait.

## Consequences

`docs/architecture/lock-order.md` records, for each lock, the level at which it is taken.
