# Phase 0 review by A10 (QA)

Date: 2026-10-31. Reviewed commit: `dde257e`. Scope: ADR-0001 to ADR-0012, `sdk/include/kamos/*.h`,
`docs/architecture/lock-order.md`, `docs/roadmap.md`, `docs/coordination/`, provenance register,
build and test evidence (BOARD rows P0-04 to P0-08, P0-10, P0-11).

## Independence caveat

This review and the replays below were run by the same Claude Code session that produced the
A02 changes in `dde257e` (resumable `build-cross.sh`, reproducible ISO). It is a replay from clean
clones, not an independent verification. The evidence entries stay marked accordingly, and a
separate A10 session should repeat the replay before the gate is signed.

## Verdict

**Not signed.** The Phase 0 criterion "A10 finds no contradiction in the ADRs" is not met: four
design defects (D01 to D04) and one consistency defect (D05) are open. Build and test criteria
are met (see replay results). Nothing here is a claim about Windows compatibility.

## Defects

| ID | Severity | Owner | Finding |
|---|---|---|---|
| D01 | High | A01, with A03 and A05 | ADR-0009 says the level "is stored in CR8". CR8 is the local APIC task priority and masks nothing while the legacy PIC delivers interrupts, and v0.1 uses the PIC and PIT (ADR-0001 and the Phase 2 deliverables). As written, raising to `DISPATCH_LEVEL` would not keep the timer interrupt out. The ADR must say how v0.1 enforces levels (software level plus PIC masks and deferred interrupts, or LAPIC and TPR enabled in Phase 2). Blocks the Wave 1 gate. |
| D02 | High | A06, A01 freezes | `SeAccessCheck` cannot be reached from the open path. `ObReferenceObjectByName(Path, Type, Object)` has no desired access and no caller token, `ObCreateObject` takes no security descriptor, and nothing inserts a named object into the namespace. Phase 7 would need an ABI change, which is the circular dependency the plan wanted to avoid (plan section 1.3, point 4). Fix before Wave 3. |
| D03 | High | A03 (boot info), A04 (address spaces), A06 and A07 (handle tables) | Missing cross-agent contracts. (a) No header defines the boot information handed to the kernel (memory map, modules, framebuffer), yet A04 depends on it and A07 needs the initrd module. (b) `mm.h` maps pages only "in the current address space"; there is no way to create an address space or map into another one, which `PsCreateProcessFromImage` needs. (c) `ob.h` has no create, destroy or clone function for `HANDLE_TABLE`, while the plan requires handle inheritance. Blocks A04 (Wave 2) and A07 (Wave 3). |
| D04 | High | A05, A01 | `ke.h` and `lock-order.md` gaps. (a) No DPC and no work item, although ADR-0009 mentions DPCs, `ob.h` defers deletion "out of DISPATCH_LEVEL", and an interrupt handler (DEVICE_LEVEL) cannot call `IoCompleteRequest`, which is documented for up to DISPATCH_LEVEL. (b) `KEVENT` is opaque and there is no `KeInitializeEvent`, so no caller can create one; `EVENT_TYPE` is unused. (c) `KSPIN_LOCK` carries no rank, so the debug-build lock-order assertion promised by `lock-order.md` cannot be written. (d) Ranks 10 to 30 are "held at PASSIVE_LEVEL" but no blocking lock primitive exists. |
| D05 | Medium | A01 | Inconsistencies. ADR-0007 says every failing function returns `NTSTATUS`, but `MmAllocatePool` and `MmCreateKernelStack` return NULL. `status.h` defines `STATUS_CANCELLED` (used by `io.h`) but ADR-0007's initial set omits it. ADR-0007 names `KeBugCheck`, the header declares `KeBugCheckEx`. ADR-0009 says blocking waits assert `PASSIVE_LEVEL`, `ke.h` allows `DISPATCH_LEVEL` with a zero timeout. |
| D06 | Medium | A01, A10 | The 16 `NTSTATUS` values in `status.h` were compared with my recollection of the public values, not against [MS-ERREF]. No discrepancy found, but this is not a verification. ADR-0007 states the customer bit is one "public code never uses"; that is unverified and should be worded as a convention. |
| D07 | Medium | A01, A10 | ADR-0006 says the stub bytes were "checked 2026-10-30 against `sandbox/win/src/service_resolver_64.cc`" with no repository revision, so nobody can replay the check. The provenance register has no entry for it. |
| D08 | Medium | Founder, lawyer | ADR-0012 allows black-box observation of a licensed Windows 11 VM and references published SDK headers. The Windows licence terms on that use, and the redistribution terms of SDK headers, are not reviewed. ADR-0004's open point covers only licence and trademark. Not legal advice. |
| D09 | Medium | A01, A02, A10 | Referenced or planned files that do not exist: `sdk/syscalls/table.def` (ADR-0006), `docs/testing/hardware.md` (ADR-0010), `docs/architecture/overview.md` and `docs/development/toolchain.md` (plan deliverables), `tests/framework/`, `.github/workflows/`, `docs/security/threat-model.md` (created with this report), `docs/compatibility/matrix/{pe,abi,win32,chromium}.md`. The plan names `docs/status.md` and `docs/compatibility/matrix.md`; the repository uses directories instead. |
| D10 | Low | Various | `ASSERT` is always active, with no debug-only variant, although ADR-0009 speaks of "debug builds". `MmVirtualToPhysical` has no way to report an unmapped address. `docs/status/build.md` was stale (fixed in this commit). |
| D11 | Info | Founder | Deviations from the plan: 12 ADRs instead of 10; agents A09b and A11 exist in `OWNERS.md` but not in the plan's ten (the plan allows a split of A09 and a ceiling of 12 sessions, but A11 COMPAT is a new role); the repository is public from the start, where the plan's default was private until v0.1 (recorded founder decision). |
