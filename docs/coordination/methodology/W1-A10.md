## 2. Approach

**Principle: the oracle never comes from the code under test.** For each criterion the verdict rests on
one of three witnesses, in this order of preference: (a) a public specification; (b) a physical or
emulated device state that the code under test does not produce (host clock, QEMU's own interrupt
log, the 8259's request register, symbol addresses read from the ELF by `nm`); (c) a hand-written
expected value fixed before the code exists. A golden file generated by the code under test is
never an oracle, except for parser fixtures, whose verdicts are written by hand.

**Sources used** (all allowed by ADR-0012; none is in the repository, so each one is retrieved, dated
and recorded in `provenance.md` before I rely on it):
- Intel SDM vol. 3: exception and error-code chapters, the page-fault error code (paging chapter),
  local APIC and task-priority register (for D01), the 8259A datasheet for IRR/ISR/OCW3.
- OSDev wiki: PIT, 8259 PIC, `isa-debug-exit`, serial 16550. QEMU documentation for `-d int`,
  `-D`, `-icount`, `-rtc`.
- [MS-ERREF] section 2.3 (D06). Chromium source at a named revision (D07), read only, BSD-3-Clause,
  nothing copied. Multiboot2 specification (memory map types, for `boot.h`).
- My recollection of any of these is never a source. D06 was already marked "compared with
  recollection" in `p0-A10.md`; I will not repeat that.

**Design of the framework.** One header `ktest.h`, two backends selected at compile time: host
(stdout) and kernel (a sink function that A03's `HalDebugConsoleWrite` feeds). Same macros, same
line format, so A04's logic runs unchanged on both and one parser reads both. It formats numbers
itself (about thirty lines) so that it does not depend on `kprintf` while that is being written.
`KT_CHECK` records a failure and continues; `KT_REQUIRE` records and returns from the test
function (no `setjmp` in the kernel). The runner is Python 3.12 (observed installed) and applies the
grammar of ADR-0010 strictly (section 5, row 3).

**Design of the runner for timing.** It starts QEMU itself with the serial port on a pipe and stamps
each line with the host `CLOCK_MONOTONIC` on arrival. `-serial file:` (used by `tools/qemu/run-test.sh`)
cannot be stamped. The existing script stays as it is until A02 agrees to call the parser.

## 3. Alternatives rejected

| Alternative | Why it lost |
|---|---|
| Timer oracle only from a second clock inside the guest (RTC, ACPI PM timer) | In QEMU they derive from the same emulated clock family as the PIT. Kept as a cross-check, not as the verdict. The host clock is outside the guest. |
| Deterministic time with `-icount` | It decouples guest time from the host clock, so "1 % over 10 s" would measure nothing. Forbidden in the test profile. |
| Exception check by comparing the kernel's printed line with constants the kernel also uses | Circular. Replaced by `nm` addresses, SDM rules and QEMU's own `-d int` log as a third witness. |
| Unity, CMocka or googletest for the host tests | Adds third-party code (provenance entry, licence review) and cannot run in the kernel. A small own header costs less and has one protocol. |
| Extending `run-test.sh` (bash, `grep`) to parse the protocol | The current check is `^KTEST-END ... fail=0` plus exit 33. It accepts a kernel that ran zero tests (see section 6). A parser with fixtures can be tested; a grep cannot. |
| AFL++ for fuzzing | Not installed (`afl-fuzz` absent). clang 18.1.3 builds `-fsanitize=fuzzer,address` here (observed). libFuzzer is the first choice, as ADR-0010 allows. Fuzzing starts when A09's parser exists, not in Wave 1. |
| Doing the replay (deliverable 2) first, as the brief orders | A03 waits for the oracles and A04 for the harness (BOARD W1-07, W1-08). The replay needs no one and takes the machine's two cores for builds. I propose to put it after them (question to A01). |

## 4. Order of work

Each slice ends in something that builds or reads on its own, with its evidence line.

1. **Contracts that two agents code against** (largest uncertainty, blocks A03 and A04). Write
   `oracles-wave1.md` and the host-test layout; ask A03/A04/A01 the open questions of section 7.
   Output: the serial line grammar with the extra detail fields, the exit-value map, the exception

   parser with good and bad fixtures. Evidence: `make test-host`, canaries killed, fixtures verdicts.
3. **Re-review of RFC-0001 and D06, D07, D09** (paper work, no dependency; lets the gate be
   signed). Evidence: the report, `provenance.md` entries, BOARD defects.
4. **Independent replay** of the 13 evidence rows from clean clones, one build at a time (WSL is
   limited to 4 GB and 2 cores, observed).
5. **Kernel backend and QEMU runner.** Blocked until A03 delivers a console and a long-mode entry
   (Phase 1) and A02 delivers kernel build rules (W1-06). Until then the kernel backend can only be
   checked for compiling with the ADR-0003 flags; it will be `Implemented`, not `Tested (QEMU)`.
6. **Oracle runs for A03's Phase 1 and 2 work**, then the threat-model update (deliverable 7).
