## 2. Approach

**One seam.** The mm code never touches hardware directly. A `MM_HW_OPS` table (in
`ntoskrnl/mm/mm_hw.h`) provides: `phys_to_ptr(pa, len)` (kernel: direct map; host: a simulated
physical memory), `invlpg(va)`, `load_root(pa)` and `current_root()`, `lock_acquire/release(rank,
object)`, `current_irql()`. A03's kernel fills it in later; tests fill it with the simulator. Frame
and page sources used by the page-table code and the pool are also function tables, so a test can
wrap them to inject failures.

**Simulated physical memory** (`tests/mm/host/sim_phys.c`): a list of separately allocated regions
(base, length) that mirror the *usable* part of the test machine's memory map. Any access outside
a backed region (reserved, bad, ACPI, a hole, past RAM) is a wild physical access: the simulator
raises the stop that the test then checks. So "the frame allocator never hands out, and the page
tables never touch, a reserved range" is checked by the machine, not by the code under test. Under
ASan the simulator also poisons the pages that the frame database says are free, so a page-table
write into a freed frame is a sanitizer report.

**Frame allocator.** Boot allocator (bump, from the usable ranges minus reservations: kernel image,
modules, loader structure, first MiB, framebuffer, ACPI, passed by the caller since `boot.h` has no
kernel-image range, see section 7) places the frame database; then database (8 bytes per frame:
state, flags, reference count) plus a free bitmap with a next-fit hint. States: `FREE`, `ACTIVE`,
`PAGETABLE`, `RESERVED`, `ACPI`, `BAD`, `NONEXISTENT`. Region edges: usable ranges shrink to whole
pages, reserved ones grow. Double free, free of a non-active frame, free of an unknown or unaligned
address, reference-count overflow: bug check in every build (never `ASSERT`).

**Page tables.** Four levels, 4 KiB leaves only (large pages are read by `translate` and refused for
map, unmap and protect with an explicit status; they are not created). Map is two-phase: validate
every page and scan for collisions without writing, then write; an allocation failure in the second
phase rolls back the leaves written and prunes the tables that became empty. This is correct under
the invariant "no allocated table below the PML4 is empty, except kernel-half PDPTs", which the unmap
path keeps and the tests check after every operation. The kernel half (PML4 entries 256 to 511) has
its PDPTs pre-allocated at kernel space creation (256 frames) so that the copy made into each new
address space can never go stale. Kernel mappings are accepted only inside the mappable regions of
ADR-0005; the null guard, the top guard and the reserved range are refused.

**Pool.** Size classes 32 to 2048 bytes (carved from pages obtained from a page-provider table, one
free list per class and per pool type), large allocations directly from the provider. 16-byte header
(magic, state, class, tag, requested size) before the payload. Debug mode: allocation fill, free
fill `0xDD` verified at the next allocation of the block (write after free), 8-byte trailer canary
(overflow), wrong tag on free. Corruption: `KeBugCheckEx(KAMOS_STOP_POOL_CORRUPTION, ...)` in all
builds. Accounting by tag in a fixed 128-slot table. Zero size and size overflow return NULL
(ADR-0007 exception). The pool lock (rank 60) is never held across a call to the page provider
(which takes the address-space lock, rank 30): lock order is checked by the seam.

**Address spaces.** `ADDRESS_SPACE` = root frame + lock (rank 30). Operations on user addresses lock
the target space; operations on kernel-half addresses lock the kernel space. `Destroy` frees the
user-half tables only, refuses the kernel space and the current space (bug check).

Sources (ADR-0012, public only): Intel SDM vol. 3A chapter 4, "Paging": 4-level format,
entry formats (not cited by table number, to be pinned in provenance), canonical addresses, access rights (effective R/W and U/S are the AND over
the levels, XD the OR). AMD APM vol. 2 chapter 5 for the same layout and for the reserved bits. I will
record the exact retrieved text and date in `docs/compatibility/provenance.md` through A10's
procedure; until then the layout below is "from memory of the manuals, compared by A10's oracle
only".

**Expected entry layout (written before the code, from the manuals).** Leaf (PTE, 4 KiB): bit 0 P,
1 R/W, 2 U/S, 3 PWT, 4 PCD, 5 A, 6 D, 7 PAT, 8 G, 11:9 ignored, 51:12 physical address (bits above
MAXPHYADDR reserved, must be 0), 58:52 ignored, 62:59 protection key, 63 XD. Entry pointing to a
table (PML4E, PDPTE, PDE): bit 7 must be 0 for PML4E, and 1 means a large page for PDPTE and PDE;
bits 51:12 the table address; same P, R/W, U/S, XD. What my code must write, exactly:

| Entry | Value written |
|---|---|
| Leaf, user | `phys | P | (W ? RW : 0) | US | (X ? 0 : XD)` and nothing else (A, D, G, PWT, PCD, PAT, ignored bits, key = 0) |
| Leaf, kernel | same without US |
| Intermediate, user half | `table | P | RW | US` (XD clear: the leaf decides) |
| Intermediate, kernel half | `table | P | RW` |
| Not present | 0 exactly |

Tests compare the entry read back from the simulated memory for equality with
`x86o_pte()` of `x86_oracle.h` (A10, independent of my macros), so any extra bit is a failure, and
use `x86o_index` and `x86o_canonical48` for the walk and the canonical rule. The walker in the test
does not use my code. Bits and rules not in A10's header (PS must be 0, A and D clear, intermediate
RW) are written in the test by hand from the layout above.

## 3. Alternatives rejected

| Alternative | Why it lost |
|---|---|
| Freeing nothing on unmap and rolling back by a recorded undo log | The log is unbounded for a large range, and tables would never be returned. The no-empty-table invariant gives exact rollback with no log |
| Lazy copying of kernel PML4 entries on first fault | Needs a fault handler path in MM that ADR-0013 forbids in v0.1 (no demand paging); pre-allocating 256 frames (1 MiB) is cheap |
| Free list threaded through the free frames themselves | The frame would be read and written while "free", which defeats poisoning frames in the simulator and ties the list to the direct map. A bitmap keeps free frames untouched |
| Mocking the page tables (return codes only) | The brief requires tests that read real entries. The simulator holds real bytes |
| A heap-based simulator that uses `malloc` per page | Hides wild physical accesses in the allocator slack. Fixed regions that mirror only usable memory make a reserved-range access fatal |
| Slab pages with per-page metadata and page return | More machinery than Phase 3 needs; v0.1 keeps pages once carved (a limit, section 8). Large allocations do return their pages |
| Fuzzing with libFuzzer | The harness is ASan/UBSan unit tests (A10); randomised sequences with a model give the same bug-finding for this logic and run in `make test-host`. Fuzzing belongs to parsers (Wave 3) |

## 4. Order of work (each slice builds and tests alone, one commit each)

1. Seam, simulator, bug-check stub, test support. Hostile boot-map cases are written first, because
   the map handling carries the largest uncertainty (reservations, region edges, overlaps).
2. Boot allocator and frame database, with their tests and randomised sequences.
3. Page tables: map, unmap, protect, translate, rules, rollback, fault injection.
4. Address spaces on top (kernel half sharing, create, destroy, current).
5. Pool.
6. Design document `memory.md` (lock order 30/60/70, fixup contract with A03, kernel stack guard
   pages as design only), `docs/status/mm.md`, evidence rows, BOARD rows, inbox requests.

## 5. Verification (every test has an oracle independent of the code under test)

| Property | Test | Oracle | Evidence line |
|---|---|---|---|
| Frames tracked uniquely; none from a reserved, bad, ACPI, module, framebuffer, first-MiB or kernel range | Hostile maps (unaligned edges, adjacent, single page, nothing usable, 128 regions) | A brute-force page classifier in the test (loop over every page, no shared code), plus the simulator refusing wild access | `frames: N maps, 0 reserved frames handed out` |
| Double free, free of reserved, unaligned, unknown frame, refcount overflow stop | `setjmp` around a stub bug check; state compared before and after | Expected stop code and unchanged database snapshot | `frames: k invalid frees stop, state unchanged` |
| Allocator vs shadow set under random alloc/free/ref/deref | 20 seeds x 20,000 operations | A shadow `bool[]` in the test; free count equals popcount equals state count; sum of states equals total | `frames: random 20 seeds` |
| Exhaustion | Small machine, allocate until `STATUS_NO_MEMORY`, then free all | Count of usable frames from the brute-force classifier | same |
| PTE bit layout | Map with each of the 6 valid protections, user and kernel, read the entries back | `x86o_pte()` equality; intermediate entries by the table above; unused bits zero | `pte: n entries equal the SDM layout` |
| Rules: canonical, alignment, W+X, no READ, unknown bits, user/kernel mismatch, guards, reserved range, wrap-around, count 0, phys beyond MAXPHYADDR, collision | Table of cases, each checks the status code and that the whole structure is byte-identical to before | Hand-written expected status; snapshot equality (dump of all tables reachable from the root plus frame counts) | `rules: n rejected, nothing written` |
| Atomicity on out-of-frames | Fault injection: for N = 0, 1, 2, ... fail the Nth frame allocation of one map call until it succeeds; after each failure compare with the snapshot | Snapshot equality, frame counts equal, no empty table | `inject: map fails at every allocation point, state restored` |
| Unmap, protect | Same, plus not-mapped pages, large page refusal, TLB: `invlpg` called exactly for the pages changed in the current space | Snapshot and an `invlpg` log | `unmap/protect: ...` |
| Translate | Each mapped page returns its frame and protection; unmapped returns an error | Test model | `translate: ...` |
| Random map/unmap/protect vs model | 20 seeds x 5,000 operations in three windows (user, pool, stacks) | Model (sorted array of page -> frame, prot); every 50 operations a full independent walk must equal the model; no-empty-table invariant; frame conservation: ACTIVE + PAGETABLE counts equal data pages + tables found by the walk | `pagetable: random 20 seeds` |
| Kernel half shared | Create 3 spaces, map in the kernel half through one, read the entry through the others; user mapping in one is absent in the others | Walker over each root | `aspace: kernel half shared` |
| Destroy | Tables returned, data frames untouched, kernel space and current space refused | Frame counts before create and after destroy are equal | `aspace: create/destroy leaves counts equal` |
| Lock order and balance | The seam keeps a stack of held locks: acquire rank must exceed the top, release in LIFO order, empty stack after every call, success or error | The checker (written in the test) | `locks: order 30 < 60 < 70 on every path` |
| Pool | Alloc/free, alignment 16, size classes, large, tag accounting after every step, zero and overflow size give NULL, provider failure gives NULL with accounting unchanged | Shadow table of live allocations (address, size, tag, fill pattern verified on free); address ranges never overlap (sorted-interval check) | `pool: random 20 seeds` |
| Pool corruption stops | Write past the end, write after free, double free, wrong tag, bad header: each must stop | Expected stop code `KAMOS_STOP_POOL_CORRUPTION` | `pool: 5 corruptions detected` |
| Sanitizers work on my code | The harness's canaries run first (A10); in addition a deliberately planted off-by-one in a copy of the pool is run once and must be killed | ASan/UBSan report | recorded in the report |

Every random test prints its seed on failure and runs from fixed seeds so a failure replays. Each
negative control in the table is also run once with a deliberately broken implementation (a
mutated copy kept out of the tree: skip the W^X check, skip the rollback, skip the free check,
swap lock order) and the test must fail; the mutation results go in the report. A test that cannot
fail is not counted.

## 6. Risks

| Risk | Detection | If it happens |
|---|---|---|
| My reading of the SDM bit layout is wrong | A10's independent oracle, plus the manual comparison A10 records in provenance | Stop, fix the layout, redo the affected tests; do not change the oracle |
| The simulator hides a real-hardware issue (TLB staleness, reserved bits set by hardware, A/D bits, `invlpg` of non-current space) | Not detectable on the host | Listed as untested in `status/mm.md`; Wave 2 under QEMU re-checks with `info tlb` and a deliberate fault |
| Rollback leaves a table (leak) | No-empty-table and frame-conservation checks after every operation | Fix the code; the check stays |
| Hidden dependency on the host (pointer sizes, malloc alignment) | gcc and clang, ASan/UBSan; `-m64` only | Report |
| `phys_to_ptr` in the real kernel is not valid before the direct map exists | Cannot be tested here | Assumption A-4 in section 7; A03 and I agree on the bootstrap in Wave 2 |
| Lock-order violation by calling the provider under the pool lock | The seam checker | Fix the call site |
| Scope: pool quality (fragmentation, per-CPU) is not in the brief | None needed | Not done, stated in limits |
